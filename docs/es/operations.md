# Observability and operations

## Ops page (admin only)

**What it does.** An operational dashboard restricted to admins (navbar entry guarded by `adminGuard`): live readiness (DB, configured providers, active SSE streams parsed from `/metrics`), a link to the raw metrics, backup management and per-profile export/import.

![Observability & Ops page](screenshots/ops.png)

## Health and readiness

| Endpoint | Use |
|----------|-----|
| `GET /api/v1/health` | liveness — stable contract used by the Dockerfile HEALTHCHECK |
| `GET /api/v1/ready` | readiness — verifies DB connectivity and at least one configured provider; `503` when degraded |

The compose file defines explicit backend healthchecks; nginx and certbot start with `depends_on: condition: service_healthy`.

## Prometheus metrics

`GET /api/v1/metrics` (OpenMetrics format) exposes:

- `sibyl_http_requests_total` / `sibyl_http_request_duration_seconds`
- `sibyl_provider_requests_total`, `sibyl_provider_tokens_total{kind}`, `sibyl_provider_latency_seconds`
- `sibyl_active_sse_streams`

Optional bearer-token guard: `METRICS_TOKEN`. A ready-made Grafana dashboard is in [`docs/grafana-dashboard.json`](../grafana-dashboard.json).

## Structured logging and request correlation

With `LOG_FORMAT=json` logs are emitted as JSON and carry a `request_id` (ContextVar) generated by the `RequestContextMiddleware` — it reuses an inbound `X-Request-ID` and echoes it on the response. The id is propagated to the Multi-MCP sidecar via header and bound into Telegram flows: end-to-end tracing for every request.

## Database backup and restore

**What it does.** An opt-in background task that snapshots SQLite via the online backup API (no app lock) onto a mounted volume, with configurable interval and retention.

```env
BACKUP_ENABLED=true
BACKUP_DIR=/data/backups
# + interval and retention
```

**How to use it.**
- **From the Ops page**: "Backup database" section — snapshot list with size and date, immediate **Crea backup** (Create backup), **Ripristina** (Restore) onto a snapshot.
- **From the API** (admin, audited): `POST /v1/admin/backup`, `GET /v1/admin/backups`, `POST /v1/admin/restore`.

## Per-profile export / import

A single zip with a profile's conversations, messages, knowledge base, templates and tags: `GET /v1/admin/export` / `POST /v1/admin/import`, also available from the Ops page. Useful to migrate a profile between instances or as a selective backup.

## Production deployment

In short (details in [deploy.md](../deploy.md)):

- `docker-compose.prod.yml` with **nginx** serving the static Angular build on `/` and proxying `/api` to the backend;
- `PUBLIC_URL` automatically added to CORS;
- TLS auto-detected from certificates in `nginx/ssl/` with an optional Certbot sidecar, HTTP fallback when absent;
- multi-stage Dockerfile (`node:20-alpine` → build → `nginx:1.27-alpine`);
- remember to set `VAULT_SECRET_KEY` (a security warning is logged at startup if left at the default).
